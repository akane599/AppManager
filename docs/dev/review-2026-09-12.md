# Stability and security review — 2026-09-12

This review continues the ADB, Shizuku, permission and UAD work in `fix/adb-stability-shizuku-uad`. It covers repository-wide searches and focused tracing of privileged bootstrap/IPC, connection lifecycle, app-list cache refresh, permission reconciliation, backup extraction/restore, exported components and file sharing, native helpers, executors and build workflows. It is not a claim that every Android/OEM path has been exercised.

## Critical fixes

- **Archive extraction could write or delete outside its destination.** Containment was checked after file creation and accepted sibling paths with the same prefix. Validate canonical paths with directory boundaries before mutation; reject traversal and unsupported entry types. Preserve external symlinks themselves for backup compatibility, but reject later writes through them. Filter entries before creating/deleting files so excluded existing files survive.
- **Restore paths were interpolated into a shell command.** Double quotes still allowed shell substitution. Pass `chown` arguments through Runner's existing argument escaping.
- **Privileged authentication credentials appeared in diagnostics.** Remove native/Java bootstrap argument output, redact configuration/server information, suppress credential-bearing shell command/error logging and ADB shell echoes. New tokens use 32 random bytes; synchronize creation so concurrent startup uses one token. Bind the command server only to loopback. The predictable log pathname now rejects symbolic/hard links and non-regular files, uses mode 0600 and closes owned descriptors.

## Moderate fixes

- Reject oversized authentication frames before allocation, enforce exact nonce/proof sizes, limit handshake duration, and keep the service alive after unauthenticated disconnects or protocol errors. Closing the server also closes an active handshake socket.
- Drop a cached closed session before reconnecting; bound connection establishment and close sockets on handshake failure. Invalidate failed sessions without replaying an operation whose execution outcome is unknown.
- Recover the serial task queue after a task throws. Orderly shutdown drains queued tasks; immediate shutdown returns pending tasks and interrupts active work. Awaiting termination releases the worker's monitor.
- Permission reconciliation no longer drops changes arriving during an active run. Atomic status-only updates cannot overwrite a newer desired state or recreate deleted overrides. Bulk reconciliation does not reserve keys that can remain stuck after an earlier failure.
- Gather app metadata before cache mutation and apply targeted deletes/inserts in one transaction. Failed refreshes no longer delete entries prematurely.
- Native JAR copying retries interrupted I/O, completes partial writes and removes incomplete destination files on failure.

## Minor fixes and cleanup

- Stop UID configuration from falling through into the classpath field; parse parameter values without splitting embedded colons.
- Reuse the client stderr stream and synchronize lazy stream initialization. Forward bulk stdin writes in bulk instead of one byte at a time; preserve existing flush/reopen semantics.
- Reject null tracker matcher input before JNI; snapshot callbacks safely across concurrent changes.
- Close Gradle directory streams; retain APK build test reports, including on test failure; run host-native copy regressions before the APK build.

## Validation

The pre-change full Gradle test workflow passed on `93bbf268`. New regression coverage checks archive escapes, excluded-file preservation, external-link compatibility, executor lifecycle, permission changes during reconciliation, deleted overrides, token creation, packet bounds, concurrent framing, server rejection/recovery, stderr reuse and null matcher input. Existing tests cover app-list loading, ADB, Shizuku/settings labels, UAD parsing and other app functionality.

The host-native regression executable compiles with `cc -Wall -Wextra -Werror` and passes interrupted-read/write, short-write and failed-copy cleanup checks. Workflow YAML parsing and `git diff --check` also pass. Initial CI identified an API-27-only log flag and Robolectric fixture gaps (no-op symlink creation and reset preference caches). The flag is now guarded for older devices, and the regressions use real host symlinks and the process-owned preference store. APK publication now requires passing lint as well as unit tests. Final full Gradle tests, Android lint and APK build results are recorded in PR #2; these execute on GitHub's Android build environment because this workspace has no Android SDK.

## Deliberately deferred / device verification

- Existing authentication tokens are preserved to avoid silently breaking a running server. Previously issued or logged tokens should be explicitly rotated with a coordinated backend restart; stronger generation alone does not invalidate them.
- The legacy launcher loads JARs from external-storage fallback paths. Authenticating those files against the installed APK, or replacing this bootstrap mechanism, needs a compatibility design and device validation. The current pass does not claim this trust boundary is secured.
- Absolute backup symlinks are intentional. Canonical validation blocks archive-directed escapes; it is not a descriptor-relative extraction implementation that can eliminate all races against another process concurrently replacing destination directories.
- The repository's public development signing key is intentional. Keep production release signing separate; do not rotate the debug key silently and break update compatibility.
- Remote stdin uses pipe close/reopen to implement flush. Redesigning EOF/cancellation and cross-process descriptor ownership needs Binder/device tests; its unusual semantics were retained.
- Validate Shizuku grant/deny, binder death, mode switching, cold ADB launch, work-profile access and restore on the reported Samsung Android 16 device. JVM/CI tests cannot certify OEM permission behavior or SELinux effects.

The log stream uses Android's [AutoCloseOutputStream](https://developer.android.com/reference/android/os/ParcelFileDescriptor.AutoCloseOutputStream) and [descriptor duplication](https://developer.android.com/reference/android/os/ParcelFileDescriptor#dup(java.io.FileDescriptor)) ownership contracts.
